# PR observations and query budget

Hive's PR sweep runs every 60 seconds. Each non-terminal ledger record gets one state observation per sweep. A successful MERGED or CLOSED observation with a verified GraphQL node id is retained and ends routine state reads, including across restarts. Legacy records without a node id get one migration read before terminal filtering applies. Each state observation verifies the node id and PR creation time; a changed id replaces stale state and attribution with the current session link, or an unassigned record when no link exists. For legacy records, a PR created after first sight proves URL reuse; records without a trustworthy first-sight time are replaced conservatively. A pending attribution label gets one final opportunity after a confirmed terminal observation. Hive persists that opportunity before calling GitHub; an unsuccessful result leaves status `unlabelled` and ends historical attribution retries. Reopening or a new PR identity restores eligibility. Open PRs retain their existing retry backoff.

Discovery searches each known repository for the 100 most recently updated open PRs labelled `hive`, at most once every five minutes per running tracker. Failures use the existing per-query, repository and authentication backoff. Restarting a tracker resets the successful-search cooldown. An open search result schedules a fresh state read, so a reopened labelled PR resumes observations. A new current link association, or a newer core link observation (core keeps links only while open), also schedules verification of terminal records. This can recover an unlabelled reopened PR through its session link. Reopening an unlinked PR without the label, or outside the bounded result set, is not discovered automatically. Search hits never synthesize OPEN state with stale check data.

Missing-label/permission failures pause all label work for that repository for 15 minutes, persisted across restarts. Hive raises one repository configuration attention episode while pending label work remains; a successful retry or exhausting that work clears attention. A labeler call deferred by backoff keeps its terminal opportunity pending. Normal missing-label recovery can still create the repository label; a failure of that recovery also activates the pause. A PR replaced without current session attribution remains unlabelled unless a matching labelled search result confirms the label; a later session link schedules attribution.

Closed-bead PR attention requires a successful OPEN observation taken after the bead closed. A failed refresh or an older cached OPEN state cannot confirm that the link is stale. A known MERGED/CLOSED state clears this attention.

## Steady-state cost

`test/pr-tracking.test.mjs` exercises 20 open and 100 historical PRs over 60 one-minute sweeps. It asserts 1,200 state queries and 12 searches per repository. Without terminal filtering and the discovery cooldown, that fixture makes 7,200 state queries and 60 searches per repository.

Using the small-response measurements in [the investigation](investigations/ci-and-deploy-watching.md), state queries cost approximately one GraphQL point each. Each search adds approximately one GraphQL repository-resolution point plus one REST search request (pagination can add requests). For N open PRs and R repositories, Hive's hourly estimate is **60N + 12R GraphQL points**, plus **12R REST search requests**. This observation/discovery estimate excludes the one-time identity migration (one state query per legacy record), a maximum of one final attribution opportunity per pending terminal record, open-PR attribution retries, final transitions, relink/core-observation reconciliation, retries, restarts and other clients sharing the same GitHub budget.

At 20 open PRs in five repositories, Hive adds approximately **1,260 GraphQL points and 60 REST search requests/hour**, for observation and discovery, independent of migrated historical ledger size. With core's existing 2,400-point estimate for 20 unique open links, the combined estimate is **3,660 GraphQL points/hour**. Duplicate owner links in core add cost. Attribution failures do not add a permanent term proportional to historical records: terminal opportunities are finite, and repository configuration failures allow at most four label opportunities per repository per hour after the first failure. Other transient attribution failures on open PRs continue to use per-URL backoff.

## Shared core observer dependency

The extension consumes core through its public host API only. `host.links.get(sessionId)` exposes stored session links and derived check status/head metadata. It does not provide Hive's full state observation (raw check rollup, draft flag, merge state, title and review fields), or retain the final observation after core removes a merged/closed link. A missing link cannot prove a merge.

Core API 1.93.0 exposes URL-keyed `host.links.prObservation` snapshots and `pr:observation` events with raw checks, stable PR identity, freshness/errors and retained terminal observations. Structured [CI waits](ci-waits.md) consume this contract without additional GitHub reads. The attribution/state sweep described above retains its existing independent reads; it does not supply CI wait outcomes.

## Hive repository merge evidence

The builder merges `psjamesh/agent-wrangler-hive` PRs after the latest Hive review approves the exact head and the required `test` check is green. Use `gh pr merge <url> --merge --match-head-commit <approved-head>` without admin bypass. The queen does not merge or bump versions for Hive. The builder retains its claim until installation is verified or explicitly delegated to configured core auto-update, then closes its bead.

Both `hive_update_bead.add_evidence` and `hive_finish_bead.evidence` accept `kind: "merge"`, the PR `url`, and `merged_head`: the full actual merged PR head SHA, not the merge commit. Hive rejects missing or mismatched heads unless the latest recorded review on that bead is approved for that exact commit. Record the merge commit and check verification in `detail`. This is a check on submitted evidence, not a GitHub merge operation or independent remote verification; the builder must observe GitHub's actual merged head before submitting it. Other repositories retain their assigned delivery contracts.

Merge evidence (`merge` or `merged`, case-insensitive) submitted through these agent tools requires a PR URL for every repository, so the guard can determine which repository contract applies. Hive PR subpages and `www.github.com` URLs receive the same exact-head check. Evidence kinds are stored in lowercase. The latest review is ordered by request/round update time, so a newer cancelled or unapproved review supersedes an older approval even if the older review settled later. This guard covers agent update/finish tools; the human-only workstream completion UI remains a direct human attestation.
