# Automatic work pickup

Every enabled, fully set-up hive automatically starts scoped open work using its nearest workstream worker profile, or work explicitly marked ready when there is global work capacity. **Maximum active workers** controls concurrency across hives (default 8, 0 means Unlimited). One work bead occupies one slot, including its reviews. Each helper enrolled through the before-spawn hook occupies an additional slot in the same global budget, from its pending admission through its live binding. Known exited or archived claimants, launch sessions, reviewers and helpers release their capacity; dormant live sessions still count. An exited session keeps its binding so it can resume. Releasing capacity does not clear a bead claim, launch reservation or unsettled-write fence. The rolling start guard permits one automatic start per hive and two across all hives in 60 seconds. It remains active with Unlimited capacity. Explicit worker, review and queen-handoff launches retain their existing capacity behavior and do not consume these automatic-start debits.

The queen keeps responsibility for decomposition, priorities, dependencies, sufficiently clear briefs, readiness judgments, reviews, recovery, acceptance and integration. Pickup never closes work, launches a review, replaces a worker or merges code.

## Default workers and holds

Configure a workstream’s **Default worker** from its bead panel or select the workstream under **This hive > Agents**. Choose an installed agent, model, effort, absolute working folder and optional isolated worktree. Saving validates the selection against the host’s installed agent catalog. Each workstream has a visible **Brief template**, appended to the default worker intent: use it for repository checks, commit identity, push and PR commands, review rounds and the merge/install handoff contract. A bead inherits the nearest ancestor workstream profile, with an optional per-bead explicit readiness profile. Clearing a workstream profile permits inheritance from its parent and leaves explicit readiness marks intact.

Creation accepts `hold: true` atomically. Queen- and human-created work waits at least two minutes and until a later pickup pass before default launch. Only the queen or human can create unheld work or unhold it. Include dependencies and children in the same creation batch or create held until the brief and prerequisites are assembled. Worker- and coordinator-created follow-up beads are held for queen readiness review. New Hive-created open, unassigned leaf work with a goal and acceptance criteria starts automatically after its blocking prerequisites close. Existing unmarked beads remain held until explicitly unheld or their workstream is switched to **Auto: include existing unmarked work**. The nearest ancestor workstream with an Auto setting wins, including an explicit off setting; clearing a profile resets its Auto setting to off. Work created directly in Beads without Hive’s new-bead marker also remains held until opted in. Investigation, decision, external and idea beads are excluded from default pickup. Work with recorded waits, explicit resume conditions or open input requests does not start. Default pickup is blocked by open/unconfirmed PR records, evidence explicitly marked with kind `pr` and a URL, approved or open reviews, and explicitly recorded merge/install handoff evidence (`handoff`, `merge-wait`, `install-wait`, `delivery-wait`, `merge`, `install`). Handoff evidence is supplied by the worker or queen; wait prose and arbitrary note URLs are not parsed into these records. Prior worker launches, bindings, claims and completions preserve durable replacement-start fences even after ordinary wait prose is cleared. Explicit queen readiness can launch PR fixes despite default-only PR, handoff, approved-review, input-request and resume exclusions, while retaining the existing ownership, prerequisite, open-review, recorded-wait and reconciliation guards. Default-created marks recheck default-only exclusions through startup. Use **Hold automatic pickup** in the bead panel to keep scoped work pending, and **Unhold automatic pickup** to release that hold. The queen can also call `hive_set_pickup` with `hold: true` or `hold: false` on its own. A hold does not stop an already running worker.

Default starts create the same durable, one-attempt readiness record as explicit starts. Consumed, failed, uncertain and disarmed records never restart from the default profile; they require deliberate reconciliation and rearming. An explicit mark keeps its own launch profile. Removing explicit readiness also holds the work.

When global capacity is free, the watchdog reports `pickup_unavailable` for scoped unheld work that cannot start, naming a missing inherited workstream profile, missing working folder or a profile validation problem. Ordinary prerequisite and capacity waits do not raise this flag.

## Mark work ready

The current queen calls `hive_set_pickup`:

```json
{
  "bead_id": "hive-example",
  "ready": true,
  "profile": {
    "agent": "claude",
    "model": "sonnet",
    "effort": "medium",
    "cwd": "/path/to/repository",
    "worktree": { "auto": true },
    "intent": "Build the bounded deliverable described by this bead."
  }
}
```

The human can also mark or remove readiness in bead details. Ordinary workers and coordinators ask the queen to change readiness. Marking work requires a goal and acceptance criteria, and a validated explicit provider/model/effort/folder profile. A provider without effort controls uses an empty effort. The optional worktree specification uses the same fields as `hive_spawn_worker`. Omitting it explicitly selects a shared working folder. Terra providers, requested models and resolved model identities are refused for pickup and explicit worker launches. Explicit worker and review launches allow unresolved models or unavailable catalogs, refusing Terra when the requested or a known resolved identity identifies it. Pickup requires a resolved identity, which is saved and checked before dispatch. Catalog outages and missing provider/model information hold an existing mark without consuming it; Hive retries validation on later passes, tries other eligible beads in the same hive, and notifies the queen at most once per readiness token and cause. Rearming resets these notice receipts. A changed resolved identity requires reconciliation and rearming; no substitute is selected. Working folders are limited to 2,000 characters at mark time and launch time.

The marking response includes the current `pickup.state`, `eligible`, all `reasons` and any `blocking_session_ids`, including on an idempotent repeat. A mark authorizes one launch attempt. Repeating an unused, unchanged mark is idempotent. Direct claims and manual worker launches also consume an active mark. Returning work to pickup requires `rearm: true`, the mark's `expected_token`, a reason and reconciliation of any old claim/session/launch. Removing readiness cancels a pending start before it claims work; it does not stop a worker already running.

Eligibility is stricter than a planning queue: work must be open, unassigned, below this hive's goal, without open descendants, reviews, write fences, explicit waits or missing/unresolved blocking prerequisites. The task and current queen must be available; an idle or dormant queen is fine. A queen transition suspends pickup. Live untracked descendants also suspend pickup across the cell; the hold names their session ids. Dormant, archived, exited and other sessions without live terminals remain visible in `attention.untracked_descendants` without imposing this hold. Armed work may wait for a dependency or capacity; details and `hive_ready.pickup` explain why. `hive_ready.ready` preserves manual planning candidates, including decision items, recorded/native waits and unsettled writes or reservations when they otherwise meet its open/unassigned/leaf criteria. Missing blocking prerequisites conservatively exclude candidates. Each entry's `pickup` field and the separate `hive_ready.pickup` list explain the stricter automatic eligibility, so a planning candidate is never an automatic launch authorization.

A continuous reconciliation hold observed for five minutes raises `pickup_held` in the queen’s watchdog digest, with every reason and the live untracked sessions to reconcile. The per-hive `pickupHeldMinutes` setting controls this threshold. Cell-state, live untracked descendant, profile, receipt, version, brief and hierarchy problems qualify; ordinary prerequisite, recorded wait, open descendant/review, capacity and rate holds do not wake the queen. The flag clears when reconciliation holds resolve, on launch or on disarming. One arm token receives one notification per continuous reconciliation episode, even when reasons or blocking sessions change.

## Durable authorization and recovery

Readiness is a journaled Beads field. A native-version receipt confirms the arming write. Unexpected external edits, including claim/release or close/reopen between sweeps, hold readiness. Recognized Hive summary and evidence edits advance a matching receipt. Changes to the executable brief, kind, parent/hive or profile require a fresh mark.

Worker reservation, token consumption, rate debit and fairness cursor are saved together before host spawn. The shared worker startup path rechecks authorization and claims/binds work before the first agent action. One coalescing runtime dispatcher visits hives round-robin; priority, arming time and bead id order work within a hive. Own writes request a pass, with the regular sweep covering missed events. Rendering never launches work.

A failed or unknown start is never retried automatically. Its durable token tombstone survives operation-history pruning and process restart. Unknown outcomes reserve capacity until reconciled with `hive_reconcile_worker_launch` or their known session exits or is archived. Their bead remains fenced against a duplicate launch until reconciled. Details show **Starting worker**, **Pickup needs attention** or the consumed state with the launch id and reason. A failed attempt is reported to the current queen once; an uncertain notification is not resent. Replacement runtimes observe existing attempts rather than replaying spawn.

## Design interpretation

Each explicit readiness mark carries its own launch profile; eligible unmarked scoped work uses its nearest workstream profile. Without a default, explicit marks still launch and the watchdog names unmarked work that cannot start. No additional per-hive concurrency limit, launch allowance, spend pause or usage permission applies. The start-rate guards prevent bursts; they are not spending limits.

## Dependency waits

Closing a prerequisite means its result has been delivered. For PR-backed work the queen merges, keep the bead open through merge and any required install. The builder reports the reviewed PR and verification, records `waiting_for` as "Awaiting queen merge/install of PR …", adds `merge-wait` or `install-wait` evidence for the handoff, then releases its claim with status `open` for the queen to claim and finish after delivery. This preserves the delivery wait without leaving unclaimed `in_progress` work. Opening a PR or passing review must not release dependent work.

Scope prerequisites with `hive_link_beads` (`type: "blocks"`). Work waits until every blocking prerequisite closes, including normal and external beads. An open decision or investigation prerequisite labels the map **Waiting on design**. Link-derived waiting needs no hand-set status.

When the last prerequisite closes, Hive clears link-only `deferred` status to `open` and clears that status's `waiting_for` annotation. Independent wait text on `open` or `in_progress` work is preserved, including text added after prerequisites closed. Claims stay with their holders; resuming claimed work uses the normal claim/admission check. The queen gets one `prerequisites_resolved` watchdog notification per observed resolution event, persisted across restarts. The attention item is consumed when delivery is attempted, so queen handoffs do not replay old resolutions. Startup with historical closed links alone creates no event; existing linked deferred work is still repaired. Eligible scoped unclaimed work uses the default profile; already-armed unclaimed work proceeds through automatic pickup with the same arm token and the usual capacity, profile, brief and native-version safeguards. Hive's own wait-resolution write preserves a valid pickup receipt; it cannot repair a receipt invalidated by an unrelated native edit.

Creating work, explicitly setting status on update/release, or removing a resume condition cannot establish `deferred` without an open blocking prerequisite, `resume_after_bead`, or `resume_review_at`. A create batch may include the prerequisite and its link together. Set a resume condition with `hive_update_bead` for calendar or prerequisite review; either explicit condition raises `deferred_due` for the queen, and links closing do not clear it. `waiting_for` is explanatory text, not a condition. For example, create an external release bead and link it rather than writing only "after the release ships".

Existing prose-only deferred records stay readable and editable and can be released without changing status. They immediately raise `unstructured_wait` in watchdog attention so the queen can add the missing condition. The default age reminder for legacy deferred work still applies. Missing prerequisite records never count as completed or permit automatic pickup. Disabled hives, captured snapshots and incomplete reads do not trigger wait resolution.

On upgrade, legacy `blocked` beads migrate to `open`, preserving their ownership, links, `waiting_for` annotations and resume conditions. The queen receives a durable, once-only watchdog notice naming each migrated bead. Captured snapshots and disabled cells are untouched. Waiting is derived from open blocking prerequisites (including external beads); decision and investigation prerequisites show **Waiting on design**. Resume annotations retained by migration still raise their scheduled review reminders. A migrated annotation tied to open prerequisites clears when those same prerequisites close; later edits to the annotation and independent waits are preserved.
